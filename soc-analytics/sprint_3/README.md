# Спринт 3: Расследование инцидента с брутфорсом SSH, боковым перемещением и эксфильтрацией данных

## Описание
Расследование целевой атаки на инфраструктуру Demo Lab, произошедшей 8 марта 2025 года. Злоумышленник с внешнего IP-адреса 45.227.255.186 осуществил брутфорс SSH на Linux-сервер 10.0.1.254, успешно аутентифицировался под учётной записью service_account, загрузил вредоносное ПО, выполнил боковое перемещение на Windows-сервер 10.0.0.15, похитил конфиденциальные документы и эксфильтрировал их на C2-сервер, после чего скрыл следы.

## Цели
- Провести анализ логов Linux, Windows и сетевых логов в ELK.
- Восстановить полную хронологию атаки.
- Выявить индикаторы компрометации (IoC).
- Настроить 5 правил корреляции для автоматического обнаружения аналогичных атак.
- Создать дашборд в Kibana с 5 визуализациями.
- Сопоставить атаку с MITRE ATT&CK.
- Разработать рекомендации по усилению защиты.

## Инструменты
- **ELK Stack** — анализ логов (linux_auth, winlogs, networklogs).
- **Elastic Security** — настройка правил корреляции.
- **Kibana** — создание дашбордов (Lens, Visualize Library).
- **MITRE ATT&CK** — классификация техник атаки.

### Настроены правила корреляции (5 шт.):
1. **Брутфорс SSH-атака** (>5 неудачных попыток за 10 минут).
2. **Успешная компрометация после брутфорса** (последовательность: failure → success).
3. **Массовый доступ к конфиденциальным файлам** (>5 файлов за 15 минут).
4. **Аномальный исходящий трафик** (>1 MB на нестандартный порт).
5. **Полная цепочка атаки APT** (от брутфорса до эксфильтрации).

### Создан дашборд с 5 визуализациями:
1. Неудачные попытки входа по SSH (bar chart).
2. Подозрительный исходящий трафик (line chart).
3. Доступ к конфиденциальным файлам (table).
4. Количество неудачных попыток (metric).
5. Распределение источников брутфорса (pie chart).

## Рекомендации
- **Немедленно:** блокировка IP 45.227.255.186, смена пароля service_account, проверка систем на наличие /tmp/update.
- **Среднесрочно:** настройка правил корреляции, внедрение 2FA, белые списки на входящий трафик.
- **Долгосрочно:** принцип минимальных привилегий, регулярное тестирование безопасности, аудит учётных записей.
